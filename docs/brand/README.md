# 花生片 Penaup 品牌与界面语言

## 叙事方向

“选择照片 → 相纸落入画布 → 六色显影扫描 → 写入设备 → 电子纸刷新 → 留下”是 Web、微信小程序和后续 iOS 的共同故事线。每一步都同时提供文字、进度和可恢复动作；动效是过程提示，不是硬件成功证据。

## 视觉系统

- 纸白 `#F5F5F0`、墨黑 `#171816`、线灰 `#D8D9D1`；
- 六色是电子纸的基础颜料：黑、白、红、黄、蓝、绿；通过叠色、网点与抖动，产品叙事可表达为 48 种显影色彩观感；
- 标题使用宋体/衬线，技术标签使用等宽字体，正文使用系统无衬线；
- 纸张、相框、细线和克制阴影组成层次，不使用紫色渐变或通用 SaaS 卡片；
- 交互 180–320ms，章节 420–700ms；`prefers-reduced-motion` 时关闭非必要动画。
- 语录默认使用端内短句库，保证断网时仍能创作；联网只用于明确配置的设备服务，不为换一句引入第三方请求。
- Web 大图的缩放、抖动和 film 打包默认在 Worker 中运行；不支持 Worker 时保留同步降级，不能因为性能降级改变六色文件契约。
- AI provider 的事实约束和模板输出边界见 [ai-prompts.md](ai-prompts.md)；活跃 Node Runtime 与历史 FastAPI 回滚材料都不得把六色描述成“颜色少一点”。

## 色彩与功耗

“六色”描述的是 `.film` 文件和 EPD 输出的基础色表，不是用户最终看到的色彩层次上限。Web、小程序或未来 iOS 在生成画面时，可以用叠色、网点和抖动把六种基础颜料组合成 48 种显影色彩观感；文件仍然只写入已兼容的六色索引，不新增固件色码。

颜色更丰富也不意味着像手机一样持续耗电。电子纸主要在写入/刷新时消耗能量，画面停住后不需要背光持续点亮；因此品牌文案应同时表达“48 色显影”和“低功耗留存”，避免把六色说成“颜色少一点”或把静态画面说成完全零能耗。

## 状态文案

| 状态 | 推荐文案 | 禁止文案 |
|---|---|---|
| preparing | 相纸已经落入画布 | 正在完成 |
| transferring | 正在写入六色相纸 | 上传成功 |
| refreshing | 电子纸正在刷新 | 马上就好 |
| device_state_uncertain | 已写入，等待刷新确认 | 已完成 |
| failed | 没关系，原图和草稿还在 | 发生未知错误 |

所有按钮至少 44px（小程序使用相应 rpx），键盘和 VoiceOver 必须能到达；焦点轮廓、空态、加载态、错误态和断网态与正常态同样经过设计。
