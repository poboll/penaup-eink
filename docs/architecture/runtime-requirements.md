# Penaup Runtime 需求说明

> Copyright (c) 2026 poboll
> SPDX-License-Identifier: LicenseRef-Poboll-NonCommercial

本文替代早期“film-hub”产品化描述，定义花生片 Penaup 的最小可上线服务边界。`film-hub` 作为历史目录名和 FastAPI 迁移关键词保留在代码中，但不再是用户-facing 产品名。

## 1. 产品目标

花生片不是把原始相册上传到云端再等待渲染的相框，而是把一瞬间本地显影、写进彩色电子纸。服务端的职责应保持窄而可靠：登记设备、保存已转换 `.film`、下发 Wi-Fi 命令，并把状态实时呈现给维护者。

## 2. 第一阶段范围

### 必须具备

- Node.js 24 单体运行时，可单进程启动；
- Fastify HTTP API 与静态 Web 工具托管；
- SQLite WAL 保存设备、媒体、命令和事件索引；
- 本地 `data/media/` 保存 `.film`，不保存原始照片；
- 设备首次心跳自动注册并获得 token，后续心跳校验 token；
- 管理端查看在线状态、最近心跳、电量、事件和媒体数量；
- 管理端上传 `.film`、通过固定 `latest.film` 地址供设备拉取；
- 管理端排队 `refresh`、`download_film`、`set_config` 等固件可执行命令；
- 可选 MQTT 状态/命令桥，未配置 broker 时核心链路仍可工作；
- SSE 事件流或等价的带鉴权实时更新能力；
- 无 MQTT 时健康检查、心跳、上传、下载和轮询管理可独立验收。

### 暂不纳入首阶段

- Redis、PostgreSQL、Kafka、Kubernetes 或微服务拆分；
- 服务端替代 Web/小程序完成完整图像抖动和 `.film` 转换；
- 用户社交、公开相册、云端原图备份；
- 没有数据来源证明的 AI 生图、自动排版和商业 SaaS 计费；
- 把 MQTT 作为照片存储或唯一设备真相；
- 未经授权把历史 FastAPI API 宣称为新运行时已完全兼容。

## 3. 用户与设备故事

```text
打开花生片工具
  → 选择照片 / 相机 / 模板
  → 端侧本地裁切、六色化和生成 .film
  → BLE 近场发送，或上传到局域网 Runtime
  → 设备心跳取回 latest.film
  → 管理端看到“已连接 / 正在写屏 / 已留下”
```

任何阶段失败都要告诉用户下一步：未连接设备、转换失败、写入中断、Wi-Fi 未连接、token 失效、文件不存在，而不是只显示通用“请求失败”。

## 4. 功能需求

| 编号 | 需求 | 验收 |
|---|---|---|
| R-01 | 健康检查 | `GET /health` 返回产品名、运行时和 MQTT 是否启用 |
| R-02 | 首次心跳 | 新 `device_id` 返回唯一 token 和心跳间隔 |
| R-03 | 心跳鉴权 | 已登记设备 token 错误返回 401，不覆盖旧状态 |
| R-04 | 在线判断 | 最后心跳超过约 3 个周期显示离线 |
| R-05 | 媒体写入 | 管理 API 只接收大小受限且通过三机型头部/长度校验的 `.film`，文件名净化，写入本地目录 |
| R-06 | 媒体读取 | 设备凭 token 获取指定文件或最近 `.film` |
| R-07 | 命令队列 | 命令按设备、按创建顺序交付一次，并写事件记录 |
| R-08 | 实时状态 | 管理端收到心跳、命令和媒体事件后及时更新 |
| R-09 | MQTT 可选 | broker 不可用时 HTTP/BLE 主链路不崩溃；可用时仅同步状态/命令 |
| R-10 | 数据边界 | 原始照片、密码、token 不进入服务端日志和仓库 |
| R-11 | 版权边界 | 新增代码/文档标记 `poboll`；历史第三方来源保留原许可 |
| R-12 | 三机型 | STD/Pro/Max 生成的 `.film` 尺寸和设备识别不混用 |

## 5. 非功能要求

- **部署**：单人可在一台局域网机器上用 `npm install && npm test && npm start` 启动；
- **默认安全**：默认只监听 `127.0.0.1`；暴露局域网前设置 `PENAUP_ADMIN_TOKEN`，并用 HTTPS 或可信内网保护；
- **性能**：设备心跳和管理查询应在本地 SQLite 下保持低延迟；照片不经服务端重编码，避免 CPU 和内存峰值；
- **资源**：SQLite 使用 WAL；媒体按文件流写入，不把整个文件复制进 JSON 或事件表；SSE 客户端断开后释放监听器；
- **可恢复**：`server/data/` 可整体备份；数据库和媒体索引不应依赖临时缓存；
- **可观测**：健康检查、事件表和结构化日志能区分设备、媒体、命令和 MQTT 来源；
- **可迁移**：未来规模超过单机能力时，保留 API 语义，替换 SQLite 和本地存储即可，不先引入无需求的分布式组件。

## 6. 客户端要求

### Web

- 适配 Chromium Web Bluetooth；
- 选择设备后根据 `PENAUP/PENAUPPRO/PENAUPMAX` 或历史名称选择 STD/Pro/Max 配置；
- 保持照片处理在本地，并在“显影 → 发送 → 写屏”阶段显示可理解的状态动画；
- `prefers-reduced-motion` 下自动退化为淡入、进度和结果状态。

### 微信小程序

- 使用 ES5 兼容语法和统一 `ble-utils.js`；
- 连接页同时识别 Penaup 与 FrameFilm 历史广播名；
- 使用同一套 `.film` 头、色表和像素布局；
- 传输失败提供重试，不丢失用户当前草稿；
- 所有高风险操作（恢复出厂、格式化、OTA）必须二次确认。

### iOS / 原生 App 参考

原生 iOS App 不属于当前仓库的构建目标，但产品体验可沿用同一状态模型：`draft → processing → sending → writing → done / failed`。实时活动、锁屏状态或通知只能展示脱敏的设备名、阶段和百分比，不展示照片内容、token 或局域网地址。

## 7. 运营与数据策略

- 默认本地优先，不建立用户账户和云端相册；
- Runtime 的 `data/` 属于部署者私有数据，备份前由部署者确认权限；
- 清理媒体前必须区分当前 latest、设备尚未下载的文件和可删除历史文件；
- 第三方 broker、图像模型、字体、数据手册和外包交付材料必须在发布包中单独声明来源；
- 非商业许可证不等于第三方文件可以任意再许可，见 [provenance.md](../legal/provenance.md)。

## 8. 交付门槛

第一阶段完成定义：

1. `server` 测试通过；
2. 无 MQTT 运行时能通过健康、心跳、命令、上传和 latest 下载测试；
3. 管理端可看到真实设备心跳并在事件更新后刷新；
4. STD、Pro、Max 的 `.film` 头和主体大小有夹具测试；
5. BLE 命令文档包含 `0x00..0x41` 已实现范围；
6. 小程序 JS、WXSS import、JSON 和 Web JS 通过静态检查；
7. 固件三机型构建或明确记录具体工具链/硬件阻塞；
8. 版权、密钥、旧品牌和第三方许可扫描没有未解释的阻塞项。
