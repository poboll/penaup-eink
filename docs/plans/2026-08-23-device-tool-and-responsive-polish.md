# Penaup 设备工具与响应式体验实施计划

> **For Codex:** 按现有 `codex/penaup-eink-rebuild` 分支逐项实现，并在每个阶段运行对应门禁。

**目标：** 把花生片 Web 工作台打磨成桌面与移动端一致的纸面体验，并提供一个只复用已核实 BLE 命令、不会误报结果的浏览器设备工具。

**架构：** `/studio/` 继续负责选择、裁切、六色显影和传输；新增 `/device/` 作为设备维护入口，独立拥有 BLE 连接、状态刷新、网络清除、恢复出厂和 BLE OTA 状态机。固件升级包由 `manifest.json + .bin` 组成，浏览器在写入前完成型号、大小和 SHA-256 校验；Web Serial 只保留能力探测和硬件门禁说明，不猜测 USB bootloader 地址或协议。

**技术栈：** 原生 HTML/CSS/ES5/ES6、Web Bluetooth、Web Crypto SHA-256、Fastify 静态资源、Node.js 24、现有 `film-core` 与 BLE 帧契约。

---

## 本轮验收标准

- 工作台所有主要按钮在 390、768、1024、1440px 下使用统一栅格，按钮最小高度 48px，底部导航等宽对齐。
- 页面正文、状态、恢复提示和网络说明不再依赖 10px 以下的关键信息字号；Reduced Motion、键盘焦点和 44px 触控目标保持可用。
- `/device/` 在没有设备时也能完整展示能力边界和错误恢复路径；连接取消、断开、重置网络、恢复出厂和 OTA 失败都不会卡死页面。
- 网络清除使用已核实的 `0x3B`，恢复出厂使用已核实的 `0x22`，OTA 使用现有 `0x10 → 0x11×N → 0x13`；不新增协议值。
- OTA 在写完 `OTA_STOP` 后显示“等待重新广播/状态待确认”，只有重新连接并重新读取状态后才能结束维护流程；不把 BLE 写入完成冒充实体刷新成功。
- 固件包必须通过型号、协议、文件长度和 SHA-256 校验；仓库没有真实发布包时，UI 明确显示“暂无已签名发布包”，不伪造版本。
- Node 检查、服务端/film-core/微信测试、浏览器 DOM/截图审计和 `npm audit` 全部通过。

## 参考边界

- iOS `PeanupApp` 的纸面 tokens、TransferRail、`device_state_uncertain` 和本地优先原则用于交互对齐；不修改参考项目。
- Dot 页面只用于只读信息架构参考；不在第三方真实设备上点击重置、升级、断开或上传数据。
- 历史 `FrameFilm` 协议名保留为兼容词；新界面只显示“花生片 Penaup”。

## 实施结果（2026-08-24）

- `/device/` 已落地 BLE 连接、状态回读、网络配置、网络清除、重启、恢复出厂和安全 OTA 门禁；没有正式镜像或固定公钥时，刷写按钮保持锁定。
- `/studio/` 不再保留直接 `.bin` OTA 上传入口；固件升级、网络清除、恢复出厂和重启统一从 `/device/` 进入，创作工作台的快捷维护命令只显示“状态待确认”，不会把 BLE 写入回执当成成功。
- `/studio/` 已统一网络、设备控制、显影和上传按钮栅格；网络折叠状态同时更新视觉箭头和无障碍属性。
- IAB 桌面回归已验证首页、工作台和设备工具无页面异常；响应式 CSS 契约覆盖 420/560/720/820/1024px 断点，创作、转换和设置页的主要操作目标保持 48px，重置类图标操作保持 44px 触控目标。当前 IAB 未提供稳定的 390/768px 模拟视口，移动截图仍列为发布前验收项。
- `npm run check`：严格环境下契约检查 235 passed、0 pending、0 failed；另有 105 个 JavaScript 文件语法通过。ESP-IDF 5.5.2 已导出并完成 STD/Pro/Max 三机型代码构建，应用分区余量分别为 13%/12%/14%；实体刷写仍需真实硬件验收。
- `npm test`：服务端 43、film-core 8、微信 18、Web/发布工具 20 全部通过；`npm run audit`：0 vulnerabilities。

本计划对应的代码和文档会作为一次大更新提交到 `codex/penaup-eink-rebuild`，只推送到 `poboll/penaup-eink`；旧 `origin` 远程不参与本轮发布。
