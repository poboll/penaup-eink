# 微信读书 × 花生片壁纸实验室设计

> Copyright (c) 2026 poboll · `LicenseRef-Poboll-NonCommercial`

## 目标

把微信读书里的阅读记录变成一张适合花生片 Pro 的 3.68 英寸 E6 屏保。输出固定为 `PENAUP_PRO`、`792 × 528`，网页负责排版与显影，设备只接收经过校验的 `.film`。

这里的“48 种色彩观感”指六种物理墨水经过叠色、网点和抖动形成的空间组合，不新增固件颜色编码。画面刷新后不需要持续发光，低功耗是电子纸的工作方式，不是删减色彩换来的。

## 方案取舍

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| 服务端渲染 | Node 调微信读书并在服务器生成图片 | 需要图像运行时和字体渲染，增加媒体留存与隐私边界 |
| 浏览器本地显影 | Node 只做一次性上游转发；浏览器用汇文明朝体、Canvas Worker 和 `film-core` 生成 PNG / `.film` | **采用**：轻量、可离线重排、Key 和阅读摘要不落库 |
| 独立壁纸服务 | 另起 Next.js / 队列 / 对象存储 | 与单人维护和低资源目标冲突，暂不引入 |

## 用户流程

```text
输入临时 Skill Key
  → 连接并读取书架摘要
  → 选择时间范围与壁纸场景
  → 纸面预览 / 调整显影方式
  → 本地六色 Worker 生成
  → 下载 PNG、.film，或发送到已连接 Pro
```

首发场景：

- 本周阅读小票：把本周时长、天数、书目和摘录排成一张窄边编辑小票；
- 本月阅读日历：用每日阅读柱和书名标记形成一张月历；
- 书架标本：把读过的书变成纸质书脊和书架层板；
- 我的读书卡：选择一本书，展示进度、简介与最近划线/批注。

所有场景共用同一份归一化数据，不直接依赖微信读书原始字段。上游 API 只在请求期间使用用户输入的 Key；服务端不保存 Key、书架、原文、图片或生成文件。

## API 边界

```text
POST /api/v1/integrations/weread/connect       # 验证 Key，只返回数量
POST /api/v1/integrations/weread/bookshelf     # 返回书架最小字段
POST /api/v1/integrations/weread/snapshot      # 周/月阅读统计
POST /api/v1/integrations/weread/reading-card  # 单本书最小卡片信息
```

请求统一使用 `X-Penaup-WeRead-Key`，响应 `Cache-Control: no-store`。可选的丰富数据请求采用固定上限和并发上限；上游书摘或书架补充失败时，保留统计摘要并明确显示“部分资料未取回”，不能把失败数据伪造成完整成功。

## 视觉与无障碍

网页使用偏白的糙米纸面、细纸纤维、墨黑正文和六色小面积强调。大标题使用汇文明朝体，统计和协议使用等宽字。关键正文不小于 `14px`，主要按钮至少 `48px`，移动端场景选择改为纵向卡片。显影扫描、纸张落位和完成回看分别对应真实阶段；`prefers-reduced-motion: reduce` 时只保留淡入和进度变化。

## 失败与恢复

- Key 缺失、格式错误或被拒绝：不访问上游，保留输入焦点；
- 上游超时：保留上一次已完成的画面，不清空草稿，提供重试；
- Worker 不可用：允许看本地普通预览，但禁用 `.film` 下载和发送；
- Pro 未连接：允许下载，发送按钮解释如何连接；
- BLE 写入后未读回设备状态：进入 `device_state_uncertain`，不显示成功。

## 验收标准

- 四个场景都能在 `792 × 528` 画布上生成可读的本地预览；
- 三种显影方式复用 `packages/film-core` 的统一定义，输出仍通过 `.film` 校验；
- 390、768、1024、1440px 下无横向溢出，键盘和减少动态可用；
- 服务端测试覆盖 Key 不回显、上游请求体、月份/日期归一化、读书卡最小字段和可选富化失败；
- 未使用真实 Key 做自动化测试，发布前轮换曾在开发对话中暴露的 Key。
