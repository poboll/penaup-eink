# 花生片首页与显影工作台纸面实验室收口设计

## 本轮目标

把首页和 Web 工作台收口成同一张接近白色的灰白草纸：能看到很轻的纤维方向，但不抢走产品图、标题和显影结果。页面的叙事仍然是花生片自己的“编辑台”，不是把参考站的代码、纹理图片或文案搬进来。

视觉参考只用于研究以下可观察特征：浅色草纸底、细黑线、纸片错位、手工裁切般的小圆角和低对比阴影。纹理由本仓库的 CSS 层生成，依赖低成本的渐变，不新增第三方图片或运行时请求。

## 首页构图

- Hero 产品图后不再使用大圆形光晕，改为两张错位纸片、登记线、纸胶带和轻微的产品投影；这样产品仍是视觉主体，也保留“相片落在纸面上”的故事语气。
- 首页原有展示字体继续用于产品叙事标题。它不是电子纸字体，也不会被 WeRead 的壁纸字体选择替换。
- 48 色展示采用 6 行 × 8 列的纸样矩阵：行代表六种物理基色，列代表显影层级。叠色、网点、抖动只改变矩阵里的标记方式，不能被理解成新增 42 种独立墨水。
- 页面文案同时明确“最多 48 种色彩观感”和电子纸的低功耗特征：静态画面不需要像手机一样持续点亮，但仍会受写入、刷新、面板与电池影响，不承诺零能耗。

## 工作台交互

工作台沿用同一套纸面 token，并把连续操作收敛为清晰的四步：选择照片/取回记录 → 纸面排版 → 六色显影 → 下载或发送。主要按钮保持至少 48px 高，移动端不压缩多行中文；操作区域与 Pro 的 528 × 792 竖向视觉相纸共用居中基线。

微信读书壁纸实验室允许在开始显影前选择“汇文明朝体”或“系统宋体”。字体只改变浏览器本地 Canvas 的排版，不改变 film-core 的六色编码、画布尺寸、协议方向或设备传输。换字体时保留当前阅读数据并重新排版；取回记录前切换字体则只更新待生成提示。

示例数据仍完全在浏览器内生成，便于首次使用者看到四阶段状态；真实 Skill Key 只通过临时请求头转发，不写入 URL、localStorage、数据库、日志或返回体。

## 兼容与验收

- Pro 视觉画布固定为 `528 × 792`，历史 `.film` 仍为 `792 × 528`，不修改六色索引、BLE 192 字节分块或固件协议。
- `paper-finish-contract.test.mjs` 锁定首页六行八列矩阵、三种显影模式和纸面覆盖层。
- `weread-wallpaper-contract.test.mjs` 锁定两种字体、动态字体状态和本地排版边界。
- 发布前继续检查 390/768/1024/1440px、键盘焦点、Reduced Motion、下载失败重试、设备状态待确认和浏览器控制台；没有签名固件时，设备工具仍不得开放 OTA 刷写。
